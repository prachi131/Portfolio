Redesigning Trust in EV Charging Discovery & Booking

EV drivers couldn't trust whether a charger would actually be available when they arrived — causing anxiety, wasted trips, and booking confusion. I validated this through research with 25 EV users and redesigned the full experience from discovery to payment.

The Problem
Core user frustration
"I never know if the charger I'm heading to is actually free — and when I get there, the booking system is so confusing I just give up."
Research · 25 EV Users Interviewed
⚡
Pain Point 1 — Availability
No real-time visibility on charger status before arriving. Users had to physically drive to the station to find out if it was occupied.
"I've wasted 20 minutes driving to a charger that was already taken. There's no way to know in advance."
🗓
Pain Point 2 — Booking
Time-slot selection was deeply ambiguous. Users weren't sure if their booking was confirmed, leading to double-booking and frustration.
"Did I book it? It didn't show me a confirmation. I ended up booking the same slot twice."
🔍
Pain Point 3 — Discovery
Finding a nearby charger required navigating 4+ screens before any useful availability information was visible to the user.
"By the time I find the charger info I actually need, I've tapped through five different screens."

03 — Confirmed
Key Design Decisions
🟢
Color + Icon Status System
Green / Amber / Red pins on the map itself — users see charger status before tapping anything. Eliminates the "drive and find out" problem entirely.
📅
Visual Slot Grid
Replaced confusing text-based time selection with a scannable visual grid. Available, taken, and selected states are colour-coded — no ambiguity.
🛡
Trust Indicators
Added reliability score, rating, and session count to each station card. Users can make confident decisions before spending time navigating there.
📋
"What Happens Next" State
Booking confirmation now shows 3 clear next steps — replacing a blank "success" screen that left users unsure whether anything had actually worked.
What I Learned
01
Research reveals the real problem
I assumed the issue was "bad UI". After 25 interviews, the real problem was trust — users didn't believe the system. That realization changed my entire design direction.
02
Confirmation matters as much as the action
The booking flow technically worked — but users didn't feel it worked. Explicit confirmation + "what's next" resolved anxiety without any backend change.
03
Visual encoding beats text labels
Replacing "Available: Yes/No" text with a colour system let users process status at a glance — reducing cognitive load exactly when anxiety is highest.
